v2.2.1（2026-07-19） ​

FFmpeg 路径修复与内核升级

  • 修复自定义 FFmpeg 路径：环境检查与 serve 现在使用同一个可执行文件，不再依赖文件名必须为 ffmpeg（#77）；
  • 音频-only mp3/flac 转码逻辑下沉到 uiya-yutto 内核的 resolve_audio_save_codec，前端不再显式覆盖编码（#74）；
  • 内核升级至 uiya-yutto 0.2.4；
  • 项目以 AGPL-3.0-only 许可证发布。

v2.2.0（2026-07-18） ​

迁移到常驻 yutto server —— 解析与下载不再逐次启动子进程抓日志，改由一个随应用 自动启停的后台 server 驱动，结构化事件实时回传。

  • 收藏夹 / 合集解析大幅提速，列表边解析边逐条平滑出现；
  • 下载卡片显示阶段（解析中 / 写入附件 / 下载中 / 后处理中）与实时进度条 （百分比 · 已下载 / 总量 · 速率），不再需要去控制台看进度；
  • 下载队列串行执行，显著降低触发 B 站风控的概率；
  • 修复仅音频 MP3 / FLAC 下载在合并阶段必然失败的问题（现在自动转码）；
  • 保存设置会自动重启 server，下载目录 / FFmpeg / Python 的修改立即生效；
  • 内核升级至 uiya-yutto 0.2.1。

升级后需要知道的变化

  • 画质菜单总是显示完整档位（最高 8K），实际画质下载时自动降级，选高了不会失败 —— 详见 画质菜单与批量下载画质说明；
  • 队列串行是刻意设计（防风控），同一时刻只有一个任务在下载，其余显示「排队中」；
  • 正在解析 / 下载时保存设置会中断这些任务（设置页会先提示）；
  • 之前用 MP3 / FLAC 仅音频下载失败过的用户，现在可以再试了；
  • 疑难解答从应用内移到了本文档站点，应用内的入口会直接打开本站。

v2.1.0（2026-07-11） ​

批量解析提速

  • 内核升级至 uiya-yutto 0.1.0，合集 / 收藏夹批量解析并发执行，等待时间大幅缩短；
  • 新增「解析并发数」设置项；
  • 批量解析时单个视频失败不再中断整体任务；
  • VitePress 文档站点上线。

v2.0.2（2026-07-05） ​

下载目录可配置与疑难解答

  • 下载目录可独立配置，不再绑定根目录；
  • 应用内疑难解答页面（v2.2.0 起移至本文档站点）；
  • 音频格式选择（M4A / MP3 / FLAC / WAV）；
  • 非首页懒加载，优化启动速度。
